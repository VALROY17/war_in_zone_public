📖 Гайд: сюжетное событие и ивент-флаги

В этом гайде мы добавим в игру сюжетное событие — «Подкрепление», а затем свяжем его со вторым событием через ивент-флаг, чтобы продемонстрировать цепочку: «подкрепление пришло → позже группа получила награду».

💡 Почему сюжетные события — мощный инструмент
В отличие от случайных событий, сюжетные:
  • Привязаны к конкретной территории (Zona)
  • Привязаны к конкретному ходу (Step)
  • Поддерживают ивент-флаги — переменные сюжета для ветвления
  • Имеют 35 типов действий (против 22 у случайных)
Это основной инструмент для создания сюжетных модов.

🎯 Что получится в итоге

  • Событие 1 — на ходу 10 на территории 159 группировка получает подкрепление: 2 новичка и 1 опытный боец
  • Событие 2 — на ходу 15, если событие 1 сработало (флаг установлен), группировка получает премию 5000 денег
  • События связаны через ивент-флаг: второе не сработает без первого
  • Оба события отображаются с иконкой, текстом и звуком

📋 Что нужно подготовить

  • Одно изображение для иконки события (формат PNG, размер как у существующих — смотрите в data\gfx\icons\)
  • Один звуковой файл (формат MP3, опционально)
💡 Минимум графики для теста
Для проверки можно использовать иконки и звуки из стандартного сценария. В реальном конфиге используется путь gfx\icons\story_SHOC\0.png для иконки и sfx\events\message.mp3 для звука. Их можно временно указать в своём событии.

📝 Пошаговая инструкция

Шаг 1. Создайте секцию события 1 в Events_Story.ini

Откройте файл Events_Story.ini в папке вашего сценария (или создайте его, если его нет). Каждое событие — это отдельная секция [Название_события]. Название секции само по себе является ивент-флагом.

Добавьте в конец файла секцию первого события — «Подкрепление». За основу структуры возьмём реальный конфиг (Event-Cordon-1, тип MCMove), но с типом AddUnits:

[Event-Reinforcement-1]
Step=10
Zona=159
Type=AddUnits
CountUnit1=2
CountUnit2=1
CountUnit3=0
CountUnit4=0
EventFlagResult=FlagReinforcement
EventFlagStatusSet=True
Img=gfx\icons\story_SHOC\0.png
ShowForOwner=True
ShowForNonOwner=False
AddToGameLog=True
SoundFXForOwner=True
SoundFXForOwnerFile=sfx\events\message.mp3
NotWorkFractions=Mutants,Zombie
📌 Разбор параметров
  • Step=10 — событие сработает на 10-м ходу
  • Zona=159 — индекс территории, к которой привязано событие (обязательный параметр, даже для чисто информационных событий)
  • Type=AddUnits — тип события: добавить юнитов владельцу территории
  • CountUnit1=2 — 2 новичка, CountUnit2=1 — 1 опытный, CountUnit3=0, CountUnit4=0 — ветеранов и мастеров не добавляем
  • EventFlagResult=FlagReinforcement + EventFlagStatusSet=True — после срабатывания события установить ивент-флаг FlagReinforcement в True
  • ShowForOwner=True, ShowForNonOwner=False — показывать только владельцу территории
  • AddToGameLog=True — добавить сообщение в лог игровых событий
  • NotWorkFractions=Mutants,Zombie — событие не сработает у Мутантов и Зомби

Шаг 2. Создайте секцию события 2 с ивент-флагом

Теперь добавим второе событие, которое сработает только если флаг FlagReinforcement установлен (то есть событие 1 произошло). Добавляем его в тот же Events_Story.ini:

[Event-Reinforcement-2]
Step=15
Zona=159
Type=AddResources
NameResources=Money
CountResources=5000
EventFlag=FlagReinforcement
EventFlagStatusNeed=True
EventFlagResult=FlagReinforcement
EventFlagStatusSet=False
Img=gfx\icons\story_SHOC\0.png
ShowForOwner=True
ShowForNonOwner=False
AddToGameLog=True
SoundFXForOwner=True
SoundFXForOwnerFile=sfx\events\message.mp3
NotWorkFractions=Mutants,Zombie
📌 Как работает ивент-флаг в этом событии
  • EventFlag=FlagReinforcement — имя флага, состояние которого проверяется
  • EventFlagStatusNeed=True — событие сработает, только если флаг FlagReinforcement установлен в True (то есть событие 1 произошло)
  • EventFlagResult=FlagReinforcement + EventFlagStatusSet=False — после срабатывания события флаг сбрасывается в False (он больше не нужен)
  • NameResources=Money — техническое название ресурса из папки Goods/
  • CountResources=5000 — точное количество денег (у сюжетных событий всегда точное значение, в отличие от диапазона у случайных)
⚠️ Только один тип на событие
В одной секции [Event-XXX] может быть только один параметр Type. Если нужно сделать несколько действий — создайте несколько событий с одинаковыми Step и Zona либо свяжите их ивент-флагами, как мы сделали.

Шаг 3. Добавьте локализацию в messages.csv

Откройте messages.csv и добавьте строки для обоих событий — название и описание. Имя секции события используется в ключе:

[Events_Story.Event-Reinforcement-1].Name;Подкрепление
[Events_Story.Event-Reinforcement-1].Desc;К вашей группировке присоединились новые бойцы: 2 новичка и 1 опытный.
[Events_Story.Event-Reinforcement-2].Name;Награда за службу
[Events_Story.Event-Reinforcement-2].Desc;За проявленную доблесть ваша группировка получила премию в 5000 денег.
⚠️ Формат ключа

Ключ должен точно совпадать с именем секции в квадратных скобках. У нас секция называется Event-Reinforcement-1, значит ключ — [Events_Story.Event-Reinforcement-1].

Регистр значения не имеет, но рекомендуется писать так же, как имя секции. Разделитель — точка с запятой ;, внутри текста её использовать нельзя.

Шаг 4. Включите сюжетные события в Settings.ini (если нужно)

Сюжетные события включаются и отключаются через Settings.ini:

[Main]
; ...
EventsStoryDefault=True        ; ← состояние по умолчанию в меню (True = включены)
EventsStoryCanChange=True      ; ← может ли игрок отключить их перед стартом
; ...
💡 Обычно это уже настроено
В стандартном сценарии эти параметры уже установлены в True. Править их нужно только если вы хотите по умолчанию отключить сюжетные события или запретить игроку их включать.

Шаг 5. Сохраните все файлы в правильной кодировке

  • Events_Story.ini — UTF-8 с BOM
  • messages.csv — UTF-8 с BOM
  • Settings.ini (если правили) — UTF-8 с BOM

✅ Проверка результата

  1. Запустите игру и начните свой сценарий за группировку, владеющую территорией 159
  2. Перед стартом убедитесь, что в меню настроек сюжетные события включены
  3. Доживите до 10-го хода — должно сработать событие «Подкрепление»: на территории 159 появятся 2 новичка и 1 опытный, отобразится сообщение
  4. Доживите до 15-го хода — должно сработать событие «Награда за службу»: на склад поступит 5000 денег
  5. Проверьте лог игровых событий — оба события должны быть там записаны
  6. Тест ветвления: начните игру заново и убедитесь, что если событие 1 не сработало (например, играете за Мутантов из NotWorkFractions), то событие 2 тоже не сработает, даже если дожить до 15-го хода

⚠️ Вероятные ошибки

Событие не срабатывает на нужном ходу
  • Проверьте, что параметр Zona указан и совпадает с реальной территорией, которой владеет нужная группировка
  • Проверьте Step — ход, на котором сработает событие
  • Убедитесь, что в Settings.ini параметр EventsStoryDefault=True
  • Проверьте NotWorkFractions — не исключена ли ваша группировка
Второе событие срабатывает без первого

Проверьте параметры ивент-флага во втором событии:

  • EventFlag=FlagReinforcement — имя флага должно совпадать с тем, что устанавливает первое событие (EventFlagResult=FlagReinforcement)
  • EventFlagStatusNeed=True — флаг должен быть установлен для срабатывания
Событие срабатывает повторно каждый ход

Одноразовое событие не должно срабатывать повторно. Если это происходит:

  • Проверьте, что Step задан конкретным числом (например, 10), а не 0. Значение 0 или пустое делает событие вневременным
  • Если вы намеренно используете Step=0 и хотите повторение — добавьте Repeatable=True. Без него вневременное событие сработает один раз
Движок выдаёт ошибку на загрузке
  • Проверьте, что Type — один из 35 допустимых типов (см. справку)
  • Проверьте, что в секции указан только один параметр Type
  • Проверьте, что все обязательные параметры для выбранного типа указаны. Для AddUnits — CountUnit1…4, для AddResources — NameResources и CountResources
💡 Нюанс: любое событие требует территорию

Каждое сюжетное событие привязано к территории через параметр Zona. Это касается не только вторжений или ресурсов, но и чисто информационных событий (Info), и даже смены лидера (ChangeLeader). Без Zona событие не сработает.

💡 Нюанс: имя секции = ивент-флаг

Название секции события само по себе является ивент-флагом. Когда событие выполняется, флаг с его именем автоматически устанавливается в True. Это можно использовать для проверок через EventFlag в других событиях.

Все ивент-флаги при старте сценария движок сбрасывает в False, поэтому их не нужно прописывать в Main.ini.

⚠️ Зарезервированные флаги

Флаги EndVictory и EndLose зарезервированы движком:

  • EndVictory — при установке сценарий завершается победой (если в Settings.ini включено End-EventFlag-Victory=True)
  • EndLose — при установке сценарий завершается поражением (если End-EventFlag-Lose=True)

Не используйте эти имена для своих промежуточных флагов.

🔗 Связанные разделы справки

  • Events_Story.ini — полное описание 35 типов событий и системы ивент-флагов
  • RandomEvents — случайные события (22 типа, без привязки к территории)
  • SpecialEvents — глобальные механики (выброс, пси-излучение)
  • Settings.ini — EventsStoryDefault, EventsStoryCanChange, End-EventFlag-Victory, End-EventFlag-Lose
  • messages.csv — ключи [Events_Story.*]
  • Achievements.ini — достижения типа EventFlag
  • Лимиты движка — 35 типов захардкожены, добавить новый нельзя
  • Рудименты и «не трогать» — запрет отрицательного CountParam
  • Кодировка файлов — UTF-8 с BOM
