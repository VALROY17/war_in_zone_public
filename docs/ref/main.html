⚙ Главный конфиг сценария (Main.ini)

Файл Main.ini — центральный конфиг сценария. Здесь задаётся состояние игрового мира на старте: кто чем владеет, какие у группировок лидеры, заместители, идеологии, ресурсы, бойцы, дипломатия и состояние территорий.

💡 Динамика vs статика
Main.ini хранит динамичные параметры — те, что меняются в процессе игры (владелец территории, число бойцов, активность мутантов).
Статичные настройки (можно ли игроку переключать пси-установку, стоимость действий, условия победы) живут в Settings.ini. Это разделение подробно описано в совете №8.
⚠️ Наследование от data\default\
Если в вашем сценарии нет Main.ini — игра подгрузит дефолтный файл из data\default\Main.ini. См. Структура сценария.

🚫 Секции, которые трогать НЕ надо

Следующие секции либо перезаписываются движком при старте, либо не имеют смысла для редактирования. Подробности — в «Рудименты и «не трогать»».

СекцияПочему не трогаем
[Scenario]Все параметры (ActivePlayerIndex, BurstEnabled, RandomEventsEnabled, StoryEventsEnabled, MoveArmyThroughAllyEnabled и др.) движок перезаписывает при старте на основе настроек из Settings.ini и того, что выберет игрок в окне настроек сценария в игре
[EventFlag]Все ивент-флаги движок сам сбрасывает в False при старте сценария. Сами флаги задаются в Events_Story.ini
[ProcessedItemCount]Число произведённой амуниции в рамках текущего хода. Трогать только если нужно ограничить производство на первом ходу

🧠 [PsyControl] — состояние пси-установок на старте

ПараметрТипОписание
BrainPsy@@BOOLВключён ли пси-излучатель на старте сценария. Возможность им управлять в процессе игры — в Settings.ini → BrainPsy-PlayerCanChangeStatus
BrainMixer@@BOOLВключён ли выжигатель мозгов на старте сценария. Аналогично — управление через Settings.ini
💡 Это старт, а не возможность
BrainPsy=True здесь значит «установка работает со старта». Но сможет ли игрок её включать/выключать в процессе игры — задаётся в Settings.ini (BrainPsy-PlayerCanChangeStatus, BrainControlChangeBasedCost, список зон влияния и т.д.), а у бота — в его AI.ini. См. Механика пси-излучения.

🏰 [MainZoneFraction] — главные базы группировок

У каждой группировки есть одна главная база. Её потеря приводит к потере части ресурсов (BasedPercentLostResources + BonusPercentLostResources), кроме LockedResources.

ПараметрТипОписание
<Группировка>@@ЦЕЛОЕ Индекс территории, которая является главной базой этой группировки. Формат: Stalkers=85
 
[MainZoneFraction]
Stalkers=85
Bandits=112
Soldiers=166
Duty=79
Freedom=71
Monolith=7
Mercenaries=84
Scientists=108
Zombie=63
💡 Индекс территории
Индекс соответствует номеру секции [ZonaX] ниже. Индекс не обязан совпадать с номером территории на карте — это внутренний идентификатор, который использует движок.

👥 [Advisors] — доступность заместителей в сценарии

Список всех кандидатов из Advisors.ini, которые доступны в этом сценарии со старта.

ПараметрТипОписание
<ТехНазвание>@@BOOL True — заместитель доступен в меню назначения, False — скрыт. Формат: Advisor-Stalkers-Wolf=True
⚠️ Доступен ≠ назначен
Этот блок только делает кандидата видимым в меню. Кто реально назначен заместителем со старта — задаётся в секции [Group-Advisor] ниже.

🤝 [Diplomacy] — отношения между группировками

Пары «группировка-группировка» со значениями от -1 до 3.

ЗначениеСтатус
-1🔴 Вечная война (нельзя заключить мир)
0⚔ Война
1🕊 Нейтралитет
2🤝 Союз
3💎 Нерушимый союз (нельзя разорвать)
 
[Diplomacy]
Mutants-Stalkers=-1
Stalkers-Bandits=0
Soldiers-Scientists=2
Monolith-Zombie=2
...
📌 Формат ключа
Ключ — пара через дефис: GroupA-GroupB=значение. Техническое название группировки — из файла Groups (имя файла без .ini).
💡 Дипломатия симметрична
Движок считает отношения двусторонними: если задать Stalkers-Bandits=0, то и Bandits-Stalkers автоматически считается равным 0. Достаточно прописать одну строку для каждой пары. Но в дефолтном Main.ini для наглядности прописаны обе — это не ошибка, а стиль разработчика.

🎖 [Group-UnitIndex] — шаблоны юнитов

Привязка рангов бойцов к техническим названиям шаблонов. Жёсткий лимит движка: ровно 4 ранга на группировку.

ПараметрТипОписание
<Группировка>-<Ранг>@@НАЗВАНИЕ Техническое название шаблона юнита. Формат: Stalkers-1=Stalkers1 (где 1 — новичок)
🎯 Ранги
1 = новичок, 2 = опытный, 3 = ветеран, 4 = мастер. Это же используется в Goods → параметр Level.

👑 [Group-Leaders] — лидеры группировок

ПараметрТипОписание
<Группировка>@@НАЗВАНИЕ Техническое имя лидера из файлов leaders/ (имя файла без .ini). Формат: Stalkers=Leader-1

👥 [Group-Advisor] — кто назначен со старта

ПараметрТипОписание
<Группировка>@@НАЗВАНИЕ Техническое имя заместителя из Advisors.ini (из квадратных скобок []). Этот кандидат должен быть True в [Advisors]. Формат: Stalkers=Advisor-Stalkers-1

📜 [Group-Rules] — внутренние правила группировок

У каждой группировки есть ровно 4 слота правил (Rule1, Rule2, Rule3, Rule4). В каждый слот записывается индекс правила из Rules.ini.

ПараметрТипОписание
<Группировка>-Rule<N>@@ЦЕЛОЕ Формат: Stalkers-Rule1=2, Stalkers-Rule2=6, Stalkers-Rule3=12, Stalkers-Rule4=17

🏛 [Group-Ideology] — стартовая идеология

ПараметрТипОписание
<Группировка>@@НАЗВАНИЕ Техническое название идеологии из файлов ideologies/. Формат: Stalkers=Stalkers, Duty=AntiZone

⬆ [Group-Upgrades] — улучшения, купленные со старта

ПараметрТипОписание
<Группировка>@@НАЗВАНИЯ Список технических названий файлов улучшений (имя файла без .ini) из папки upgrades/, разделённых запятыми. Формат: Stalkers=Upgrade-6,Upgrade-11 — значит, на старте у сталкеров уже куплены улучшения из файлов Upgrade-6.ini и Upgrade-11.ini

🗺 [ZonaX] — параметры территорий

По одной секции на каждую территорию карты. X — индекс территории (тот самый, что используется в [MainZoneFraction] и в Settings.ini).

ПараметрТипОписание
Owner@@НАЗВАНИЕТех.название группировки-владельца. Обязательный параметр для каждой территории
Buildings-Count@@ЦЕЛОЕЧисло построек на территории
Unit1@@ЦЕЛОЕЧисло новичков гарнизона
Unit2@@ЦЕЛОЕЧисло опытных
Unit3@@ЦЕЛОЕЧисло ветеранов
Unit4@@ЦЕЛОЕЧисло мастеров
Mutant1@@ЦЕЛОЕЧисло фоновых собак
Mutant2@@ЦЕЛОЕЧисло фоновых кабанов
Mutant3@@ЦЕЛОЕЧисло фоновых кровососов
Mutant4@@ЦЕЛОЕЧисло фоновых контролёров
MutantsActive@@ЦЕЛОЕ 0-100 % активности мутантов на территории. Когда превышает ActiveMutantScaleForMutantUnitX из Settings.ini — мутанты соответствующего типа начинают появляться
NeedUnitsForBlockUpActiveMutants@@ЦЕЛОЕ Число бойцов гарнизона, необходимое, чтобы активность мутантов на территории перестала расти
NumStepAfterSearchArts@@ЦЕЛОЕ Число ходов с последнего найденного артефакта на этой территории. 
[Zona85]
Owner=stalkers
Buildings-Count=0
Unit1=4
MutantsActive=0
NeedUnitsForBlockUpActiveMutants=3
Unit2=2
Unit3=2
⚠️ Пропусков в индексах быть не должно
Секции территорий должны идти строго подряд: [Zona1], [Zona2], [Zona3], …, [ZonaN]. Если на карте 194 территории — должно быть ровно 194 секции без «дыр». В каждой секции обязательно должен быть хотя бы параметр Owner. Остальные параметры (юниты, мутанты, постройки) можно не указывать — движок подставит нули.
⚠️ Фоновые мутанты ≠ гарнизонные
Mutant1…4 — это фоновые мутанты, которые появляются при росте активности. Их нельзя победить обычным способом. Для гарнизонных мутантов (например, у группировки Mutants) используются Unit1…4.
💡 Порядок параметров не важен
В примере видно, что строки идут в произвольном порядке (Unit1, потом MutantsActive, потом снова Unit2). Движок читает их по именам, а не по порядку. Но для читаемости лучше группировать: Owner, затем Unit*, затем Mutant*, затем остальное.

🔗 Связанные разделы

  • Goods — товары для склада и экипировки
