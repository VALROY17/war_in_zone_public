📖 Сюжетные события (Events_Story.ini)

Файл содержит сюжетные события сценария — основной инструмент для создания сюжетных модов. Каждое событие привязано к конкретной территории и (опционально) к конкретному ходу, что позволяет выстраивать сложные сюжетные цепочки.

🎲 Events_Story vs RandomEvents
  • Привязка к территории — здесь обязательна (Zona=X), у случайных событий — всегда случайная.
  • Привязка к ходу — здесь обычно есть (Step=X), у случайных — нет.
  • Ивент-флаги — только здесь можно создавать ветвящийся сюжет через флаги.
  • Типов событий — здесь 35, у случайных 22.
  • Проверочные типы (Check*) — только здесь.
  • События главного героя (MCMove, MCAttack) — только здесь.
  • Числовые эффекты — здесь всегда точное значение (например, через CountParam, CountUnitX или CountResources), у случайных — часто диапазон CountMin…CountMax.
Полная сравнительная таблица — в RandomEvents.

📐 Структура одного события

Каждое событие — это отдельная секция [Название_события]. Название секции само по себе является флагом: если событие сработало, флаг с таким именем автоматически устанавливается в True.

[Event-Cordon-1]
Step=1
Zona=191
Type=MCMove
Img=gfx\icons\story_SHOC\0.png
TargetResourceImg=gfx\old\NoData_100x100.png
ShowForOwner=True
ShowForNonOwner=True
AddToGameLog=True
SoundFXForOwner=True
SoundFXForOwnerFile=sfx\events\message.mp3
SoundFXForNonOwner=True
SoundFXForNonOwnerFile=sfx\events\message.mp3
NotWorkFractions=Mutants,Bandits,Soldiers,Monolith,Mercenaries,Zombie

Основные параметры события

ПараметрТипОписание
Type@@ВЫБОР Тип события (один из 35, см. ниже). Может быть только один на событие
Zona@@ЦЕЛОЕ Обязательный. Индекс территории, к которой привязано событие. Даже чисто информационные события требуют территорию
Step@@ЦЕЛОЕ ≥0 Ход, на котором сработает событие. 0 или пустое значение = вневременное событие (проверяется каждый ход и срабатывает при выполнении условий)
Repeatable@@BOOL Может ли событие повторяться. Работает только при Step=0. Если True — событие будет срабатывать каждый ход при выполнении условий
⚠️ Только один тип на событие
В одном блоке [Event-XXX] может быть только один параметр Type. Если нужно сделать несколько действий — создайте несколько событий с одинаковым Step и Zona, либо используйте ивент-флаги для связывания.

🔍 Проверочные типы (Check*)

Эти типы не выполняют действие, а только проверяют условие. Если условие не выполнено — событие не произойдёт. Можно комбинировать с параметром Repeatable=True (событие будет происходить хоть каждый ход, пока выполняется условие) или с Step=0, если надо, чтобы произошло один раз за игру в любой ход (как только будут выполнены все условия).

ТипЧто проверяет
CheckBuildingПостроено ли указанное здание (BuildingName)
CheckUnitsЕсть ли нужное число юнитов (CountUnit1…4)
CheckResourcesЕсть ли нужное число ресурса (NameResources, CountResources)
CheckOwnerВладеет ли указанная группировка территорией
CheckIdeologyПринята ли указанная идеология
CheckUpgradeИзучено ли указанное улучшение
CheckEventFlagУстановлен ли указанный ивент-флаг
💡 Зачем нужны Check-типы
Они позволяют создавать события, которые срабатывают по условию, а не только по ходу. Например: «когда игрок построит мастерскую в Деревне новичков на Кордоне — дать ему 1000 денег и показать диалог». Событие будет вневременным (Step=0) с типом CheckBuilding и каждый ход будет проверять, построена ли мастерская.

🚩 Система ивент-флагов

Ивент-флаги — это «переменные» сюжета. Они позволяют создавать ветвящиеся цепочки событий, где последующие события зависят от того, какие предыдущие уже сработали.

ПараметрТипОписание
EventFlag@@НАЗВАНИЕ Имя флага, состояние которого требует это событие для срабатывания
EventFlagStatusNeed@@BOOL Какое состояние флага из EventFlag должно быть, чтобы событие сработало. True — флаг должен быть установлен, False — не установлен
EventFlagResult@@НАЗВАНИЕ Имя флага, которое будет изменено после успешного срабатывания события
EventFlagStatusSet@@BOOL Какое состояние установить флагу из EventFlagResult после срабатывания события

Пример ветвления через флаги

; Событие 1: устанавливаем Flag1 (невидимо для игрока)
[Event-SetFlag1]
Step=10
Zona=85
Type=Info
EventFlag=Flag1
EventFlagStatusNeed=False     ; только если Flag1 ещё не установлен
EventFlagResult=Flag1
EventFlagStatusSet=True       ; устанавливаем его
ShowForOwner=False
ShowForNonOwner=False
AddToGameLog=False

; Событие 2: сработает только если Flag1 установлен
[Event-AfterFlag1]
Step=15
Zona=85
Type=AddResources
NameResources=Comands
CountResources=10
EventFlag=Flag1
EventFlagStatusNeed=True      ; требовать установленный Flag1
EventFlagResult=Flag1
EventFlagStatusSet=False      ; отключить Flag1, так как больше не нужен
🏁 Зарезервированные флаги
  • EndVictory — при установке этого флага сценарий завершается победой (если в Settings.ini включено End-EventFlag-Victory=True)
  • EndLose — при установке сценарий завершается поражением (если End-EventFlag-Lose=True)
Все ивент-флаги при старте сценария движок сбрасывает в False. Поэтому их не нужно прописывать в Main.ini → [EventFlag].

💡 «Невидимые» служебные события
Если поставить ShowForOwner=False, ShowForNonOwner=False, AddToGameLog=False — событие сработает «за кадром», без единого упоминания. Это часто используется для установки ивент-флагов или для служебных действий (например, автоматическая смена лидера).

📋 Локализация (messages.csv)

[Events_Story.<название_события>].Name      - краткое название события
[Events_Story.<название_события>].Desc       - основной текст описания события

«Название события» — это имя секции в квадратных скобках (например, Event-Cordon-1).

⚙ Включение/выключение в меню

Игрок может включать/выключать сюжетные события перед стартом сценария. Настраивается в Settings.ini:

ПараметрОписание
EventsStoryDefaultСостояние по умолчанию в меню (True/False)
EventsStoryCanChangeМожет ли игрок переключать

🧩 Особенности и подводные камни

СитуацияПочему так
Событие с Step=0 Такое событие считается вневременным и может сработать на любом ходе при выполнении условий
Одноразовое событие не срабатывает повторно Названия сюжетных событий сами считаются флагами. Если событие выполнилось — флаг с его именем установлен. Чтобы выполнить снова — нужно сбросить флаг или использовать Repeatable=True (работает только при Step=0)
Любое событие требует территорию Каждое событие привязано к территории. Не только вторжение или ресурсы, но и чисто Info, и даже смена лидера
Флаг устанавливается «сам собой» при выполнении события Имя секции события = имя флага. Если событие выполнилось — флаг с этим именем автоматически устанавливается в True

🗂 Где ещё используется

  • Main.ini — [EventFlag] (рудимент, не трогать), [ZonaX] (индексы территорий)
  • Settings.ini — EventsStoryDefault, EventsStoryCanChange, End-EventFlag-Victory, End-EventFlag-Lose
  • Achievements.ini — Type=EventFlag, TargetFlag
  • RandomEvents — «младший брат» с 22 типами без ивент-флагов
  • SpecialEvents — глобальные механики (Выброс, Пси-излучение)
  • messages.csv — ключи [Events_Story.*]
  • Лимиты движка — 35 типов захардкожены, добавить новый нельзя
  • Рудименты и «не трогать» — запрет отрицательного CountParam
